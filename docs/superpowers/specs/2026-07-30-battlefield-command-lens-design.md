# Project Expedition 戰場指令鏡頭設計

日期：2026-07-30

狀態：玩家已核准；在衝突處取代
`2026-07-28-combo-clarity-impact-v2-design.md` 的技能格、連招軌與施放操作。

## 玩家成果

戰鬥只呈現目前需要做的決定。玩家不讀事件表，就能在三秒內辨識目前角色、
目前目標、技能結果、追加條件與施放方式；預演、演出與結算使用同一套因果
語言。

## 三狀態循環

### 選擇

- 戰場常駐完整六名角色與敵人，但只有目前角色與目前目標顯示姓名、完整 HP
  與關鍵戰鬥數值。
- 其他單位只顯示短 HP 條、狀態光點與角色輪廓。
- 六技能維持 3×2；每格最多顯示圖示、2–4 字名稱及三個結果資訊。
- 傷害使用具名值 `傷5`；多段只在它是技能特色時顯示 `2擊`；狀態顯示
  `燃+2`、`毒+2` 或 `潮+2`。
- 條件成立只顯示一個金色連招徽記，不常駐顯示條件文字。

### 預演

- 第一次點技能只設定待命技能，不造成戰鬥事件。
- 技能格不得與說明面板上下堆疊；改為六個技能切換籤、單一結果句與明確施放
  按鈕。
- 戰場直接顯示目標預計 HP、狀態前後值、攻擊路徑與受影響單位。
- 結果句使用玩家動作語言，例如：
  `造成2傷。開戰時再造成3傷。附加2燃燒。`
- 未成立條件只顯示一個當前原因，例如 `需要敵人燃燒`。
- 點敵人只切換目標與預演；不施放。唯一承諾動作是
  `對{目標名稱}施放` 按鈕。
- 詳細計算、事件與裝備來源只在主動開啟的詳情覆蓋層出現。

### 施放

- 施放期間收起指令內容並鎖定輸入，讓戰場取得完整視覺注意力。
- 演出順序固定為角色蓄力、攻擊路徑、本體命中、條件點亮、追加或反應、狀態
  變化、接力交棒。
- 傷害顯示在受傷者，狀態顯示在持有者，接力顯示在兩名角色之間。
- 播放完成後清除待命技能，自動切換下一名角色，存活目標保持鎖定。

## 戰場 HUD

- 左上角色 HUD：姓名、目前／最大 HP、攻擊與強化。
- 右上目標 HUD：姓名、目前／最大 HP、有效防禦、削弱與反擊意圖。
- HTML 人物按鈕正常狀態保持視覺透明，只保留語意與至少 48px 觸控區。
- Pixi fallback 才顯示所有人物的簡化姓名與 HP。
- 敵人意圖使用固定圖示、路徑與受擊角色標記，不使用覆蓋人物的大型文字框。

## 技能語言

- 禁止在主要戰鬥介面使用 `已亮`、`出招亮`、`缺...`、裸 `總` 或引擎事件名。
- 技能摘要依正式預演事件產生：基礎傷害、追加原因與數值、狀態變化。
- 顯示的每個總量都必須能由同畫面上的可見數字相加得到。
- 接力受益顯示在戰場上的下一位角色及其連招徽記，不顯示文字卡列表。

## 爽感語法

- 粒子數量不得作為主要升壓手段；每棒必須增加有意義的動作、命中、反應或
  接力層次。
- 本體與追加使用不同前搖、音色、停格與目標反應。
- 第三棒起保留前棒元素軌跡；第五棒鏡頭收緊；第六棒回收六人軌跡、集中狀態、
  短暫靜默後完成主爆發與 OVERKILL。
- Reduced Motion 保留輪廓、路徑、HP 預計區段、狀態前後值與因果順序。

## 技術邊界

- `simulation-core` 仍是預演、觸發、傷害、順序與正式結果的唯一來源。
- Web 只保存待命技能、目前目標與顯示投影，不重算戰鬥。
- Pixi 只播放事件與預演，不決定結果。
- 既有 Build、技能、裝備、敵人、掉落與平衡規則不在本批修改。

## 驗收

- 375×667、390×844、430×932、1280×800 都無捲動、裁切、HUD 或觸控區重疊。
- 未選技能時每格最多三個結果資訊；選中後只有一個結果句與一個主動作。
- 點敵人永遠不會意外施放技能。
- 預演與正式逐擊、HP、狀態、目標路徑、接力及 OVERKILL 完全一致。
- 戰鬥中不出現事件表、下一棒文字卡或 `起手 → 條件 → 結果` 報表。
- E2E 完成新手第一戰、六棒升壓、勝利與戰利品，且測試連接埠會關閉。
