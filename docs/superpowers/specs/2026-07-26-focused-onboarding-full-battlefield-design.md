# 聚焦式新手引導與完整戰場設計

## 目標

讓第一次進入遊戲的玩家在任何時刻只需理解一個動作，並確保手機戰場不因教學內容而縮小或裁切。

## 已確認問題

- 390 × 844 時，教學卡插入手機戰鬥網格，戰場容器縮成約 123px；敵我列實際需要約 285px。
- `.gr-battle` 固定 `height: 100dvh` 且 `overflow: hidden`，超出戰場容器的單位遭裁切。
- 同一教學訊息同時出現在大型教學卡與拇指操作區。
- 拇指操作區的教學文字約 9px、最大寬度 90px，會以省略號截斷。
- 教學未清楚標示步驟進度，也未將唯一下一步操作做視覺聚焦。

## 玩家體驗

### 公會

- 顯示「新手步驟 X/Y」與一條短指令。
- 初始直接顯示「反擊壁壘已就緒」，唯一聚焦「任務」分頁，再聚焦「開始遠征」。
- 引導中的任務卡只顯示任務名稱、一句目標及開始動作；處刑順序、專屬掉落等情報待首次教學完成後恢復。
- 每一步只允許一個元素使用教學高亮，其他操作保持可用但降低視覺優先級。

### 戰鬥

- 手機不渲染會參與排版的大型 `.gr-coach`；教學統一由拇指操作區呈現。
- 指令格式固定為「步驟 X/Y · 動作」與一條不超過兩行的說明。
- 推薦卡、撤銷、確認預演、釋放軍令依當前步驟成為唯一高亮操作。
- 戰鬥仍維持決策時停，不改變戰鬥結果或軍令因果。

### 戰利品與返回

- 每次只聚焦一件戰利品決策。
- 全部處理後，唯一高亮操作切換為「返回公會」。
- 返回後結束首次教學；設定仍可重新播放。

## 版面責任

- 手機 `.gr-battle` 使用明確區域：`header` 與 `battlefield`。
- `.gr-battlefield` 永遠占用第二個可伸縮區域，教學與固定拇指面板不得建立隱含網格列。
- 戰場內敵方、VS、我方三列必須全部位於戰場容器可見範圍。
- 高度不超過 720px 時切換為短螢幕單位卡：保留名稱、HP、處刑標記與壓力，壓縮非必要說明但不隱藏任何單位。
- 拇指面板維持固定定位，不遮住戰場；教學橫幅屬於面板自身高度預算。
- 375 × 667 與 390 × 844 都不得產生水平捲動或主要戰場裁切。

## 元件與資料流

- `createFirstHuntCoach` 回傳步驟編號、總步驟、短標題、說明及 `focusId`。
- `GuildMobileStage` 將目前手機分頁傳入引導模型，使 Build、任務、開始遠征成為可判定的不同步驟。
- `ThumbCommandDeck` 接收可選的 `guide`，渲染可讀的兩行引導，並以 `focusId` 標記唯一目標。
- `BattleThumbControls` 將卡牌或主要動作 ID 對應到 `focusId`。
- 桌機保留精簡教學卡，但不得重複顯示相同完整訊息。
- simulation-core、掉落、裝備與戰鬥結果不變。

## 錯誤與邊界

- 玩家切到非引導分頁時，引導仍指向正確分頁，不改寫存檔。
- 玩家選錯卡時，焦點切到「撤銷錯誤卡」；撤銷後回到正確推薦卡。
- 目標已正確選取時，不再要求重複選取。
- 教學關閉或完成時，不輸出 `guide`、焦點或簡化情報。
- 重新播放教學不得覆蓋既有戰績、裝備或 Build。

## 測試與驗收

- 引導模型測試每個步驟只輸出一個 `focusId`。
- 元件契約測試驗證步驟進度、完整文字、唯一 `data-guide-focus="true"`。
- CSS 契約測試驗證手機戰場只使用明確兩區，且手機 `.gr-coach` 不占版面。
- 實機完成首次流程：Build → 任務 → 開始 → 架盾 → 反擊 → 橫掃 → 預演 → 釋放 → 戰利品 → 返回。
- 375 × 667、390 × 844 實測所有戰場單位位於 `.gr-battlefield` 邊界內。
- `pnpm check` 通過後才可部署。

## 不在本批次

- 不調整敵人數值、卡牌傷害、掉落率或遊戲平衡。
- 不新增影片、配音或新的戰鬥內容。
- 不改寫桌機版整體視覺系統。
