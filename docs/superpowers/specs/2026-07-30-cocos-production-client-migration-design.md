# Project Expedition Cocos 正式客戶端遷移設計

日期：2026-07-30  
狀態：已核准方向，進入正式實作規劃

## 1. 目標

建立零引擎授權費、同一套程式可輸出 Web、Android、iOS、Windows 與 macOS
的正式玩家客戶端。第一個交付必須是一場完整狩獵，不是單一攻擊動畫 Demo：

1. 六名角色與三名敵人同時存在於完整戰場。
2. 點角色、選技能、點目標立即出招；再次點已選技能可攻擊目前目標。
3. 六名角色依序行動，每次追擊比前一次更強，最後以終結演出收束。
4. 玩家可理解技能條件、目前可觸發的組合、預估傷害及狀態變化。
5. 勝利後一頁容納最多 20 件非素材掉落，點擊才展開詳細資料。
6. 手機直式與桌面橫式皆為固定單畫面，不依賴上下捲動。

## 2. 技術選擇

採用 Cocos Creator 3.8.8 LTS。引擎與內建動畫、粒子、Tween、音效及跨平台輸出
不產生授權費或營收抽成；不依賴 Spine 或其他付費執行期。

曾評估三條路：

- PixiJS 加 Capacitor/Tauri：核心重用最高，但仍缺少可視化動畫製作管線。
- Godot 4：工具成熟，但需重寫大量 TypeScript 客戶端與橋接程式。
- Cocos Creator：直接使用 TypeScript，能保留現有核心並補足場景、動畫與輸出工具。

因此選擇 Cocos。React/Pixi 版在遷移期間維持唯讀回歸基準，不再追加新演出功能。

## 3. 架構邊界

### 保留

- `packages/simulation-core`：唯一戰鬥結果來源。
- `packages/game-data`：角色、敵人、技能、裝備、任務與掉落內容。
- `packages/shared-types`：跨套件穩定契約。
- `apps/worker-api`：雲端 API 與儲存介面。

### 新增

- `apps/game-client-cocos`：Cocos Creator 專案與所有玩家畫面。
- `packages/presentation-core`：純 TypeScript 演出規劃器，不引用 Cocos。
- `scripts/sync-cocos-runtime.mjs`：把純 ESM 核心與資料打包到 Cocos 資產目錄。

### 淘汰條件

只有在完整狩獵、戰利品、存檔及多尺寸 E2E 全部通過後，才移除
`packages/pixi-renderer` 與舊 React 玩家入口。API、模擬規則與資料不得搬進 Cocos 元件。

## 4. 資料流

```text
玩家輸入
  → Cocos CommandController
  → simulation-core
  → GuildBattleEvent[]
  → presentation-core 編譯 PresentationSequence
  → Cocos PlaybackDirector 逐節播放
  → 動畫完成事件
  → 下一節或重新開放輸入
```

播放不使用固定 `setTimeout` 推進。每個演出節點具有
`windup → travel → impact → aftermath → complete`，由動畫事件或可取消的 Tween
回報完成。跳過動畫會快速完成當前節點，但不可跳過模擬結果。

## 5. 戰場與操作

- 戰場永遠位於畫面上半部；角色本體就是可點擊目標，不另疊大型按鈕框。
- 姓名、HP 與狀態固定附著在角色腳下，使用避讓規則避免互相遮擋。
- 選中角色以腳下環、輪廓光與武器抬起表示；選中敵人以地面準星表示。
- 戰場與六格技能區之間只顯示一條「行動鏡頭」：
  `目前角色 → 技能 → 目標 → 預估結果`。
- 第一次點技能展開精簡因果提示；點有效目標出招；再點同一技能攻擊目前目標。
- 行動完成後自動選下一名存活角色，但玩家可在本回合拖曳調整剩餘順序。
- 無效操作只讓對應條件圖示搖動並指向缺少條件，不顯示長篇錯誤文字。

## 6. 技能提示

技能格常駐只顯示：

- 屬性圖示與名稱。
- 基礎值及攻擊次數，分開標示，禁止使用可能誤解成乘法的 `24 × 3`。
- 一個觸發條件圖示。
- `可連`、`差 2 層` 或 `本次會觸發` 的即時狀態。

展開後以三段圖像化因果呈現：

1. **先做什麼**：攻擊、治療、疊層、削弱或消耗。
2. **何時加演**：燃燒層數、前一招屬性、敵人狀態或隊友接力條件。
3. **這次結果**：傷害、次數、狀態前後值、會亮起的下一個技能。

所有數值取自 `simulation-core` 預演結果，Cocos 不自行估算。

## 7. 戰鬥演出語言

六個強度階層依連技次序累積，不只放大數字：

1. 單擊：角色動作、命中閃光、短震動、清楚傷害數字。
2. 接力：前後角色間出現屬性軌跡與接力音。
3. 疊層：狀態粒子附著敵人，層數以環形刻度增加。
4. 連鎖：鏡頭跟隨彈射路徑，單一敵人時產生迴響折返。
5. 爆發：消耗層數、畫面色調轉換、較長 hit-stop 與範圍衝擊波。
6. 終結：短暫聚焦、角色特寫、全隊殘影接力、擊殺／Overkill 收束。

每一擊包含預備、位移、命中停頓、衝擊、敵人受擊、數值及殘留狀態。文字只保留
名稱與必要數值；可用動作、顏色、軌跡、圖示和聲音表達的資訊不再重複成句子。
減少動態模式保留因果順序，但移除震動、閃白與高速鏡頭。

## 8. 美術與資產管線

首版採原創 2D 分件角色：身體、武器、前景特效與輪廓光分層，使用 Cocos
AnimationClip、Tween 與粒子組合。角色必須可辨識武器與姿勢，不以抽象幾何代替。

每名角色至少具備 `idle`、`selected`、`windup`、`attack`、`hit`、`victory`；
敵人增加 `break`、`defeated`。共用動作節奏，角色差異由武器路徑、元素 VFX、
命中聲與終結片段構成。所有素材保存來源、授權與生成紀錄。

## 9. 戰利品

- 素材在頂部合併計數，不占 20 件戰利品格。
- 裝備、寶石與唯一一張技能掉落共同使用 4×5 清單。
- 邊框與光柱只表示稀有度；屬性使用角落小圖示，不與稀有度混色。
- 基礎品質偏低，Overkill、連鎖擊殺與殲滅條件逐級提高品質與數量。
- 點物品在同一畫面開啟底部詳細層；關閉後回到原位置，不切頁。

## 10. 平台與品質門檻

第一批輸出 Web Desktop/Web Mobile 與 Windows。Android、iOS、macOS 共用同一場景與
輸入抽象，在第一批通過後依序產出；商店簽署與帳號費不屬於引擎成本。

完成證據必須包含：

- 核心與 presentation-core 單元測試。
- 六人完整狩獵事件順序、跳過／中斷與存檔回復測試。
- 375×812、390×844、1280×720、1920×1080 無捲動及無 HUD 遮擋驗證。
- Web 實際瀏覽器觸控／滑鼠流程與 Windows 可執行檔啟動測試。
- 60 FPS 目標；中階手機若不足則降粒子數，不改變戰鬥資訊。
- 一次完整 `pnpm check`，Cocos Web build、Windows build 與線上部署驗證。

## 11. 失敗與回復

- 無法載入資產時顯示可重試的同畫面錯誤層，不讓黑畫面取代戰場。
- 播放節點逾時會記錄節點 ID、快速完成視覺並繼續，不重算戰鬥。
- 存檔保留 schema 版本；新客戶端讀取舊存檔後立即產生可回滾備份。
- Cocos 未達功能與體驗門檻前，線上正式網址仍指向既有 React 版。
