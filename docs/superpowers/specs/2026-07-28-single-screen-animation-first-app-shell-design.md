# Project Expedition 單畫面動畫優先介面設計

日期：2026-07-28

狀態：已核准；補充並細化
`2026-07-27-formal-v1-cumulative-completion-design.md` 的行動介面契約。

## 成果

把戰鬥從縱向堆疊的資訊卡改成固定 `100dvh` 的遊戲 App Shell。戰場本身
就是角色與目標選擇器；玩家不需要離開完整戰場，就能選敵人、選出手角色、
看懂技能效果並完成六人接力。

最高視覺原則是：能用動畫、形變、顏色、粒子、音效或位置表達，就不顯示
說明文字。文字只保留名稱、技能縮寫、必要數字、主動開啟的詳細資料與真正
無法視覺化的系統錯誤。

## 固定單畫面

- 行動版戰鬥固定為 `100dvh`，頁面本身不得垂直或水平捲動。
- 完整戰場置頂，約占可用高度 68%；技能操作區置底，約占 32%。
- 移除獨立敵人卡片列、六人順序列、常駐事件紀錄、狀態長句與大型教學卡。
- 重排、沿用順序、撤離、聲音與動態設定收進右上角低頻選單。
- 詳細資料以不改變主布局的覆蓋面板或分頁呈現。

## 戰場就是操作介面

- 敵人位於戰場上半部；點擊人物直接鎖定目標。
- 我方六人位於戰場下半部；點擊仍可行動的成員，直接改為目前或下一位。
- 選中敵人以鎖定環、瞄準線與光柱表示。
- 目前角色向前一步並顯示實心光環；下一位使用虛線光環與接力光點。
- 已行動角色降低亮度；死亡角色倒下且不可選。
- 首領尺寸為一般敵人的 1.5–2 倍，具有專屬外框、氣場與舞台壓迫。
- 每個可點人物具有至少 48px 的隱形觸控範圍。
- Pixi 負責人物與特效；對齊人物位置的透明語意按鈕負責觸控、鍵盤與輔助
  科技。若 Pixi 載入失敗，仍顯示可操作的簡化人物與 HP。

## 技能區

- 當前角色的六技能固定為 2×3。
- 技能格預設只顯示屬性符號與二字縮寫。
- 條件成立以圖示脈衝、旋轉、燃燒或發光邊框表達，不常駐顯示說明。
- 點技能立即出招；長按或點詳情控制才開啟完整屬性、特化與觸發條件。
- 無法使用時以技能格震動、閃暗或角色拒絕動作回饋，不顯示錯誤段落。

## 動畫優先回饋

每次技能按輸入、蓄力、移動、命中、目標反應、狀態變化與接力順序播放。
角色必須實際做出衝刺、射擊或施法；特效不得無來源地在敵人身上生成。

- 傷害：後仰、閃白、震動與 HP 條削減。
- 燃燒：火焰隨層數升高，爆發前產生熔裂。
- 毒素：孢子與毒霧變濃，擴散時飄向其他目標。
- 潮汐：水環、護盾波紋與回流軌跡。
- 爆炸：放射衝擊波。
- 疊層：環繞目標的軌道增加。
- 削弱：護甲產生裂痕並飛散。
- 連鎖：攻擊軌跡在目標間彈射；單體迴響離開後折返同一目標。
- 強化：光環從前一角色傳向下一位。
- 多段：角色殘影與連續命中節奏。

六棒不用文字顯示進度，改由戰場邊緣六段能量逐格點亮。每棒增加動作距離、
軌跡、命中層次、粒子、鏡頭與聲音；第六棒壓暗背景、依序點亮六人、集中
引爆狀態並以全場衝擊波終結。

## 教學與其他頁面

- 新手教學使用聚光、手勢、箭頭與呼吸發光指向真實敵人、角色與技能。
- 必要提示限制為一個短動詞，例如「選敵」「選人」「出招」。
- 任務、隊伍、技能、裝備與獎勵沿用「主視覺區＋底部操作區＋固定導航」。
- 大量清單改用分類與左右分頁；詳細內容按需覆蓋，不延長主畫面。

## 技術邊界

- `simulation-core` 仍唯一決定戰鬥、觸發、傷害與順序。
- Web 只把人物點擊投影為既有選目標／選角色意圖，再播放既有事件。
- Pixi 不擁有戰鬥結果；React 不重算戰鬥。
- 可視動畫文字移除後，完整語意仍保留在 `aria-label` 與不可見 live region。
- Reduced Motion 以輪廓、顏色、姿勢與立即狀態切換保留所有資訊。

## 驗收

- 375×667、390×844、430px 戰鬥頁均無頁面捲動、裁切或操作遮擋。
- 完整戰場、目前角色、目標與六技能同時可見。
- 點戰場敵人能選目標；點我方成員能改出手角色。
- 不讀戰報也能辨識誰出手、打誰、狀態如何變化與下一位是誰。
- 六棒逐次增強，第六棒具有明確終結。
- 一般點擊回饋小於 100ms，非終結播放不超過 1.8 秒。
- Pixi fallback、Reduced Motion、鍵盤與觸控仍能完成戰鬥。
