## 1. 玩家成果

玩家不用理解「威力、特化、觸發、Component、疊層」等引擎欄位，也能在一次
技能點擊後看懂：

1. 目前目標會失去多少 HP。
2. 技能會命中幾次、影響哪些目標。
3. 會增加、消耗或轉移哪些狀態。
4. 額外效果為何成立。
5. 哪一位下一棒角色會因此變強。

正常戰鬥不顯示混合公式報表。技能的主要說明由戰場預演、角色反應、血條、
狀態光點與路徑動畫共同完成；文字只補充動畫無法表達的一個原因。

## 2. 資訊層級

### 層級 A：未選技能

- 六技能維持 3×2，無橫向捲動。
- 每格只顯示技能圖示、2–4 字名稱、對目前目標的預計總量、命中次數與一個
  主要狀態變化，例如 `30`、`×2`、`燃 +3`。
- 顯示的是 simulation-core 對目前戰況的實際預演結果，不是原始技能威力。
- 爆炸、疊層、削防、彈射、強化與多段使用固定圖形，不常駐顯示分類名稱。
- 條件已成立使用金色動態外框；可在命中後成立使用半亮外框；完全不會成立
  不顯示額外效果，但基礎效果仍保持可用。

### 層級 B：第一次點技能

- 第一次點擊只設定待命技能，不改變戰鬥狀態。
- 戰場進入半透明金色預演，主布局、戰場高度與技能格位置不得跳動。
- 目前目標 HP 條直接顯示預計扣除區段與 `目前 HP → 預計 HP`。
- 每次預計命中依序顯示個別數字；多目標顯示實際路徑與各目標結果。
- 狀態增加以新光點出現表示；狀態消耗以既有光點被吸入技能表示。
- 受強化或削弱的單位本人發光並顯示一個簡短變化數字。
- 下方原因列最多一行，例如「本回合第一位出手，因此多攻擊一次」。

### 層級 C：主動查看詳情

- 詳情分成「結果」與「計算」兩頁，不混合傷害、狀態與隊友變化。
- 結果頁按受影響單位分組，例如：敵人失去 30 HP、燃燒增加 3；萊拉攻擊
  增加 2。
- 計算頁先顯示 `原本傷害 24 + 目前加成 6 = 30`，再按需展開攻擊、技能與
  防禦來源。
- Build 研究需要的完整元件、隨機值與裝備來源保留在技能管理頁，不進入
  正常戰鬥指令區。

## 3. 戰場視覺語言

同一機制永遠使用同一視覺語法：

- 產生狀態：元素光點從施法者飛到受影響單位。
- 消耗狀態：光點從受影響單位被吸入技能後消失。
- 多段：逐次命中並顯示 `1/4` 至 `4/4`，不得只跳總傷害。
- 爆炸：目標腳下展開放射圓與衝擊波。
- 削弱：護甲圖形裂開並掉落碎片。
- 強化：能量飛向受益角色，武器或法器持續發光。
- 彈射：軌跡依結算順序連接不同敵人。
- 單體迴響：軌跡離開後繞回同一敵人。
- 接力：元素軌跡由目前角色連向下一位角色。

預演一律使用半透明金色；正式施放使用實色、命中閃光、聲音與相應鏡頭。
Reduced Motion 以靜態輪廓、HP 預計區段、狀態前後數量與路徑線保留資訊。

## 4. 人物與敵人 HUD

- Pixi 場景不得以 CSS 將 1000×560 非等比例拉成直向畫面。
- 渲染器依容器尺寸等比例輸出；直向與橫向使用各自的無重疊隊形。
- 未選單位只顯示人物、短血條與狀態光點，不常駐顯示姓名及完整 HP 數字。
- 左上保留目前角色資料；右上保留目前目標資料。其他單位點擊後才暫時替換
  對應資料。
- 目前角色使用實心腳下光環；下一位使用脈衝光環；目標使用鎖定環。
- HTML 語意按鈕保持視覺透明，觸控區至少 48px，且彼此不得相交。
- Pixi 載入失敗時才顯示 React 簡化人物、姓名、HP 與狀態。

## 5. 技能關係

- 技能不顯示抽象輸入／輸出關聯圖。
- 選中會產生狀態的技能時，相關狀態在目標身上預演，能利用該狀態的後續
  技能以相同元素脈衝提示。
- 下一棒角色若有受益技能，只顯示「下一位角色」及受益技能數量，不展開
  六人頭像或技能文字清單。
- 實際接棒後，真正受上一棒影響的技能保持發光；未受影響技能維持原狀。
- 因果順序由事件播放表達，例如：火焰落在敵人、護甲熔裂、毒霧擴散；
  不以「火 → 疊層 → 追燃 → 爆破」文字鏈代替演出。

## 6. 操作契約

1. 點敵人只改變目前目標。
2. 點我方可行動成員改變目前角色。
3. 第一次點技能設定待命並預演。
4. 再點同一技能，對目前目標施放。
5. 待命時點另一名敵人，改以該敵人為目標並立即施放。
6. 點另一技能只切換待命技能與預演，不施放。
7. 播放期間鎖定輸入；完成後清除待命並自動切到下一位角色。

螢幕閱讀器透過不可見 live region 取得與視覺預演相同的逐單位結果；可見畫面
不得因此重新加入長文字。

## 7. 技術邊界

- simulation-core 是預演與正式結果的唯一來源；React 與 Pixi 不重算傷害。
- 預演使用與正式施放相同的純函式事件序列，不改變 HP、狀態、順序或序號。
- Web 只保存待命技能與目前預演；勝利、撤離、換角、施放完成及戰鬥重建時
  必須清除。
- Pixi 只投影人物、路徑、狀態與事件；不得自行決定觸發或目標。

## 8. 驗收

- 375×667、390×844、430×932、1280×800 均無頁面捲動、畫面拉伸、人物
  HUD 遮擋或觸控區交疊。
- 第一次點技能後，玩家不開詳情即可看出目標 HP 變化、命中次數、狀態變化、
  影響範圍、額外效果來源與下一棒受益者。
- 六技能格不顯示原始威力、特化或觸發名稱，且能直接比較目前實際結果。
- 預演與正式施放的逐擊、逐目標、HP、狀態、削弱、強化、擊殺及 OVERKILL
  完全一致。
- 傷害顯示在受傷者、狀態顯示在狀態持有者、強化顯示在受益者；不得重新
  聚合成混合報表。
- 事件快照、幾何碰撞、375／390／430／1280 視覺快照、鍵盤、觸控、Pixi
  fallback 與 Reduced Motion 全部納入驗證。

- 本批不重新平衡傷害、敵人或掉落。
