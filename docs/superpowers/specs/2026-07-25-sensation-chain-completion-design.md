# Guild RPG 爽感連鎖完成度設計

Date: 2026-07-25

Status: 使用者已確認設計方向，書面規格待審閱。

## 產品目標

本批次只服務一個核心幻想：

> 玩家親手組出戰鬥引擎，釋放後看它加速成連擊、殲滅、Overkill 與掉落雨，再把戰利品裝回引擎並立刻重刷。

唯一優先順序是爽感是否連續累積。競技平衡、資源節制、數值公平與新長線系統都不是本批次目標。

完整鏈路為：

`選 Build → 看狩獵 → 開戰 → 選處刑目標 → 疊軍令 → 看預演 → 釋放 → 加速播放 → 殲滅 → 掉落雨 → 裝備 → 規則上線 → 重刷`

任何沒有把玩家推向下一個更大回饋的資訊、操作或動畫都不應加入。

## 爽感原則

1. 每次操作都要立即改變可見狀態並預告更大的結果。
2. 敵人是可被破解、串連與引爆的素材，不只是不同 HP。
3. Build 必須在選關、編排、播放、掉落與重刷五個階段持續可見。
4. 大量感由事件、材料、數字與視覺雨提供；裝備決策保持少而有意義。
5. 動畫只放大因果、破壞、連擊與成長，不製造等待。
6. 桌機與手機共享同一套決策與回饋，手機主操作維持右拇指區。

## 目前斷鏈

- 選關看不到敵人弱點、專屬掉落與目前 Build 會如何失控。
- Build 只在公會顯示一句描述，編排時缺少核心路線與觸發進度。
- 卡牌診斷使用裸露英文 tag，玩家看不到「再接一張會發生什麼」。
- 釋放後主要是事件文字與 HP 變化，缺少規則觸發、破防、擊倒與 Overkill 的視覺階梯。
- 一次勝利可能產生約十件近似裝備，掉落很多但決策疲勞。
- 裝備沒有直接說明來源、適配 Build、最佳角色與新增連動。
- 返回公會後，新裝備造成的引擎變化沒有形成立即重刷的高潮延續。

## 狩獵與 Build 預告

每個 Build 增加展示用途的 `fantasy`、`payoffLabel`、`signatureCardIds` 與 `accent`。這些資料不決定戰鬥結果。

公會的狩獵卡顯示：

- 敵人陣容、首領護衛關係與每個可破解特性；
- 目前 Build 對應的破壞方式與可作用的敵人數；
- 敵人專屬材料、裝備家族與殲滅寶箱；
- 上次紀錄與「裝備新規則後重刷」的直接入口。

三個 Build 各自承諾不同的失控方式：

- 反擊壁壘：敵方攻勢整段送回並重複反震；
- 殲滅彈射：每次命中向整群分岔並連續跳動；
- 溢療裁決：治療溢出翻轉為全場裁決與倍增。

## 戰鬥駕駛艙

戰鬥頂部固定顯示目前 Build、核心路線完成度、可用規則節點與本次狩獵殲滅目標。

敵人卡顯示：

- `蓄勢 / 即將攻擊 / 攻勢爆發` 壓力狀態；
- 預計攻擊的最高仇恨英雄；
- 護衛者、護衛解除與被哪個 Build 破解；
- 選中時改為「處刑目標」，使用更強的輪廓、標線與焦點光。

三個狩獵使用 quest CSS variables 改變背景、光線、壓力色與粒子語言。資料仍由模擬核心產生，React 只投影。

## 軍令預演與操作

`simulation-core` 提供純函式 `previewComboCommand`。它接收目前戰鬥、Build、規則與草稿，在複製狀態上執行既有解析器，回傳預估事件、傷害、擊殺、Overkill 與獎勵階梯；不修改正式戰鬥。

每加入一張卡，介面立即更新：

- 核心三卡路線完成度；
- 已建立的中文節點：格擋、命中、標記、治療、溢療；
- 預估事件、總傷害、擊殺、Overkill；
- `MULTI KILL / CHAIN WIPE / ANNIHILATION / CHEST` 解鎖階梯；
- 可接通新分支或 Build 規則的下一張卡。

所有合法卡仍可自由選擇。推薦只改變排序、亮度與說明，不代替玩家編排。不可用卡顯示中文缺失條件。

## 釋放、破壞與殲滅

正式戰鬥仍一次同步算出正確結果；播放層只逐步投影事件。

播放節奏分成：

1. `STACK`：卡牌與因果線依序點亮；
2. `TRIGGER`：Build 與裝備規則展開，節奏開始加速；
3. `BREAK`：護衛破裂、敵人連續擊倒；
4. `OVERKILL`：巨型傷害、倍率與共享溢傷持續累積；
5. `ANNIHILATION`：清場、寶箱與掉落雨無縫接續。

播放模型依事件類型產生 presentation-only impact：命中震動、治療上升、護盾擴張、擊倒破裂、Overkill 金色脈衝。後段事件批次加大以自然加速。`Skip` 直接顯示完整終局高潮。

## 掉落雨與裝備

材料數量保留倍率放大並用掉落雨呈現。需要逐件決定的裝備改為：

- 每名被擊倒敵人最多一件專屬裝備；
- Boss 與護衛同時殲滅時追加一件專屬寶箱裝備。

獵殺裝備沿用 deterministic RNG。普通無詞綴；精良與稀有一條；史詩與傳說兩條。詞綴使用既有資料表，品質影響數值強度。

裝備卡顯示來源敵人、適配 Build、規則節點、最佳角色、完整數值差與裝備後新增的連動句。預設選中提升最大的角色，按下裝備時同步點亮角色槽位與 Build 規則。

## 重刷延續

返回公會後，戰報優先顯示剛上線的裝備規則、Build 節點增量、最高 Overkill 與掉落效率。已通關狩獵提供「帶新引擎重刷」主行動，不讓流程回到無上下文的靜態首頁。

失敗流程不加入額外懲罰；直接顯示已取得材料、差一點完成的獎勵階梯與重新編排入口。

## 架構與錯誤處理

- `shared-types`：僅新增跨套件使用的 Build 展示資料、裝備適配與預演輸出契約。
- `simulation-core`：擁有預演、正式結果、詞綴與掉落數量；不用 `Math.random`。
- `game-data`：宣告 Build 爽感身份、敵人反應與裝備適配。
- `web/guild-rpg`：presenter、駕駛艙、預演 HUD、impact 與 CSS；不重算戰鬥結果。
- 預演失敗時保留自由編排與釋放，只隱藏預估值並顯示可讀提示。
- Reduced motion 移除位移與震動，但保留顏色、數字、階梯與終局狀態。
- 所有必要操作維持鍵盤、disabled semantics 與 360–430 px 右拇指操作契約。

## 驗證與完成條件

- TDD 驗證預演與正式釋放結果一致、預演不修改輸入。
- 三關 × 三 Build 內容測試驗證特性、核心卡、掉落與適配連動。
- 掉落測試驗證每敵一件、寶箱追加、deterministic 詞綴與品質成長。
- Presenter 測試驗證敵人壓力、處刑目標、推薦卡、獎勵階梯與最佳裝備角色。
- Reducer 與元件測試驗證完整鏈路沒有空畫面、死按鈕或不可完成狀態。
- 瀏覽器驗證桌機、390×844、完整殲滅、Skip、裝備、重刷與 console。
- `pnpm check`、正式 API、canonical/immutable Pages 與 live bundle 驗證作為發布閘門。

完成時，玩家從選 Build 到重刷的每一步都能看見上一個選擇造成的結果，且下一個可放大結果的操作始終清楚可達。
