# Project Expedition 因果指揮鏡頭修復設計

日期：2026-07-30

狀態：玩家已核准；在衝突處取代
`2026-07-30-battlefield-command-lens-design.md` 的 HUD、引導、技能摘要與預演規則。

## 玩家成果

玩家不需要讀事件表，就能在三秒內回答：目前誰出手、打誰、技能先做什麼、
哪個條件會追加什麼、使用後誰能接棒。所有資訊各有唯一位置，不互相遮擋。

## 單一畫面狀態

### 選擇

- 戰場常駐完整六名角色與敵人；單位身上只保留 HP 條與狀態。
- 目前角色與目標各只顯示一次姓名和數值，使用貼齊左右邊緣的緊湊 HUD。
- 移除戰場下方的角色→目標列與獨立教學列。
- 教學只在實際要點擊的敵人、角色或技能上顯示脈衝焦點及短標籤。
- 六技能維持 3×2；技能格顯示屬性、名稱、基礎結果。
- 技能有可用追加時，以完整的因果帶呈現「條件 → 追加結果」，不得使用無說明圓點。
- 未滿足時只顯示最接近成立的一個條件，保持灰階但仍可辨識。

### 預演

- 第一次點技能只待命，不造成戰鬥事件。
- 技能格留在原位作為切換籤；戰場與技能格之間只出現一個預演區。
- 預演區依序顯示：基礎效果、目前條件、追加結果；每段使用圖示、短標籤與數字。
- 顯示目標 HP 前後值、狀態前後值及下一位可接角色；不顯示引擎事件名。
- 唯一承諾動作是 `對{目標}施放`；再次點選已待命技能也可確認。
- 點敵人只換目標並更新預演，不會施放。

### 施放

- 收起所有指令說明，只保留演出狀態，讓戰場取得完整注意力。
- 演出依序呈現蓄力、路徑、命中、條件點亮、追加、狀態變化、接力交棒。
- 播放後自動選下一名角色，並以接力光束連到其可接技能。

## 戰場語言

- 目前角色只用一個實心隊伍色底環。
- 目前目標只用一個破角敵對框。
- 敵人意圖使用單一方向線與來源圖示。
- 預演落點只在選中技能時顯示；不得再疊加第二組同心圓。
- HUD、傷害數字與狀態提示不得占用同一視覺區域。

## 技能因果

- 基礎結果與追加結果必須分開，不得把總傷害和攻擊次數相鄰造成倍率誤讀。
- 條件帶必須使用正式 `comboSteps` 的 readiness，不在 React 重算戰鬥。
- `ready` 顯示成立條件與追加效果；`not-ready` 顯示唯一缺少條件。
- 下一棒只顯示一名最直接受益角色及技能，不恢復事件報表或長文字列表。
- 完整技術計算保留在無障礙標籤或主動開啟的詳情層。

## 技術與驗收

- `simulation-core` 仍是傷害、觸發、狀態、順序與結果的唯一來源。
- Web 新增純顯示模型，React 只切換選擇、預演、施放狀態。
- 375×667、390×844、430×932、1280×800 無頁面捲動與遮擋。
- 同一姓名不得在同一狀態出現兩個可見位置。
- 預演必須可見基礎、條件、追加與下一棒；不得出現無說明亮點。
- E2E 必須驗證目標點擊不施放、第二次技能點擊可施放、播放時指令收起、下一棒切換。
