# Cocos 戰鬥完成度改版設計

## 目標

在固定單畫面、無上下滑動的前提下，讓玩家於一次視線掃描內理解：

1. 現在由誰出手、打誰。
2. 選中的技能為何能或不能形成連招。
3. 會造成多少總傷、幾段攻擊、幾次額外追擊與哪些狀態變化。
4. 每一擊、觸發、彈射、迴響與接力在畫面上是不同事件。
5. 第 2 至第 6 位角色的接力演出明顯逐級升高，最後以終結演出收束。

## 根因

- 六個技能格同時顯示名稱、條件、傷害、段數與追擊，迫使文字縮小。
- `pending-impact` 被當成已滿足，玩家無法分辨「現在成立」與「命中後才觸發」。
- 模擬事件被 Cocos 壓平成通用突進與目標爆光，忽略路徑、觸發與武器差異。
- 血量與狀態在整段播放完成後才更新，打擊與結果失去因果連結。
- 角色、敵人、面板都使用相近輪廓與邊框，缺乏視覺層級。

## 採用方案

採用「技能焦點鏡頭＋五段式戰鬥節拍」。

未採用全套外部角色美術資產，因為會把本批次綁定在風格、授權與資產製作；
未採用只加粒子的方案，因為它不會修正理解與因果問題。

## 固定畫面資訊層級

- 戰場維持最大區塊，角色本體只顯示名稱、血條與非零狀態。
- 精確攻防、目標與技能因果集中在戰場和技能格之間的焦點鏡頭。
- 六個技能格只保留：屬性、名稱、總傷、連招狀態。
- 選中技能後，焦點鏡頭展開：
  - 出手者攻擊 → 目標防禦。
  - 第 1 段固定標為「起手」。
  - 後續段分成「已滿足」、「命中後接上」、「條件未滿・跳過」。
  - 總傷、攻擊段數、額外追擊次數分開標示。
  - 顯示主要狀態變化與會被點亮的下一位接力角色。
- 點敵人出招；再次點選中的技能也可對目前目標出招。

## 戰鬥播放

每個事件依序播放：

1. 蓄力：出手者反向壓縮、元素聚能。
2. 路徑：直擊、爆炸、彈射、迴響、接力各有不同軌跡。
3. 命中：屏幕閃光、鏡頭震動、傷害數字與命中音同時發生。
4. 受擊：目標後仰／壓縮；血量與狀態於該事件同步更新。
5. 回位／交棒：角色回位，接力階級亮起；第六棒顯示終結。

強度隨接力階級增加粒子、殘影、震幅、停頓與字級，不用單純放大傷害數字冒充爽感。

## 程序化角色辨識

- 六名角色保留各自色彩與武器輪廓。
- 敵人依斥候、獵手、首領等 id 產生不同耳、角、武器與體型輪廓。
- 選取框貼合角色，不再疊加另一張資訊卡。
- 未選取角色不顯示完整 HP 數字；選取後才顯示精確值。

## 驗收

- 行動裝置 390×844 無頁面捲動與 UI 相互遮擋。
- 技能格不出現「傷害數字後接 ×N」的誤解格式。
- `pending-impact` 明確顯示為「命中後接上」，不可顯示成已觸發。
- 任何出招至少有蓄力、路徑、命中、受擊、回位五個可辨識節點。
- 直擊、爆炸、彈射、迴響、接力的軌跡不可相同。
- 播放期間每個事件後的 HP／狀態可見變化與事件同步。
- 第 2 至第 6 棒的演出強度逐級上升，第 6 棒有終結標識。
- 通過 affected tests、`pnpm check`、Cocos web build 與 Cocos E2E。
