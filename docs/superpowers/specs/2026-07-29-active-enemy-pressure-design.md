# Project Expedition 主動敵軍與戰鬥壓力設計

日期：2026-07-29
狀態：玩家體驗方向已確認，進入實作

## 玩家可見成果

- 敵人不再只是等待被打的 HP；每次英雄出招前，戰場會標出即將反擊的敵人、目標與結果。
- 英雄出招後立即播放玩家因果事件，再播放一個短促敵方回應，不中斷六人接力操作。
- 防禦、生命、速度、治療與布蘭的格擋被動都會直接改變敵方回應。
- 護衛存活時會把攻擊路線拉向護衛；護衛全滅後 Boss 階段立即開啟並聚焦 Boss。
- 任務介面只使用火／草／水、六特化與觸發條件，不再要求玩家理解舊四 Build 名稱。

## 原子敵方回應

- 目前要行動的敵人按任務編成順序循環；死亡敵人自動跳過。
- 優先目標為最高威脅的存活英雄；同威脅時選生命比例較低者，再依隊伍順序決定。
- 若英雄速度高於敵人速度，結果為閃避，傷害 0。
- 否則傷害為 `max(0, 敵人攻擊 - 英雄防禦 - 格擋1)`，不使用倍率、暴擊或亂數。
- 傷害為 0 時顯示格擋；格擋在承受一次敵方回應後清除。
- 敵方回應必須產生正式事件，預演與實際結算使用同一函式。
- 英雄死亡後從本回合剩餘順序移除；全隊死亡才進入失敗狀態。

## 敵人特性與 Boss 階段

- `guardedByEnemyIds` 進入現行技能目標解析：攻擊被護衛保護的敵人時，第一個存活護衛成為有效目標。
- 舊 transform 只作內容遷移來源，映射為玩家現行語言：
  - `ricochet` → 連鎖彈射
  - `repeat` → 攻擊次數
  - `convert_element` → 水屬反應
  - `copy_next` → 強化接力
- 命中敵人公開弱點時建立一筆固定 1 點反應事件，不放大原攻擊。
- Boss 階段在指定護衛全滅後只啟動一次，留下可追蹤事件並自動選中 Boss。

## 戰場呈現

- 敵方預告直接連在戰場人物上：敵人顯示攻擊符號，目標顯示危險／格擋／閃避結果。
- 選擇技能後，英雄 HP 預演包含即將承受的敵方回應。
- 敵方回應使用獨立動畫與短音，不計入技能總傷害或追擊段數。
- 玩家演出完成後才播放敵方回應；整段仍可被下一步操作明確辨認。
- 失敗時保留戰場結果並提供返回任務，不出現無法操作的空技能列。

## 非目標

- 不增加敵人種類、技能數量、裝備數量或新貨幣。
- 不建立高難度平衡、傷害倍率、暴擊或隨機命中。
- 不在此批完成圖鑑、配置保存、正式音效資產或中斷續戰。

## 驗收

- 第一場戰鬥能看到敵方預告、格擋／傷害及英雄 HP 變化。
- 防禦提高會降低固定敵傷；速度高於敵人會閃避；治療能回復已受傷英雄。
- 敵方傷害不增加技能預估總傷害。
- 護衛會攔截受保護目標，護衛全滅後 Boss 階段只啟動一次。
- 死亡英雄不會卡住接力順序；全隊死亡顯示可退出的失敗畫面。
- 任務主畫面不顯示 Ricochet、CopyNext、反震或聖輝等舊玩法用語。
- 375、390、430px 戰場與指令區維持單畫面、無遮擋、無垂直捲動。
