# Project Expedition 完整遊玩閉環完成度改版設計

日期：2026-07-28
狀態：已確認
模式：1-to-100 Optimization

## 1. 目標

把現有 Guild RPG 從「功能存在但像原型」提升為陌生玩家不看說明也能完成、理解並願意重刷的行動裝置遊戲閉環：

`選任務 → 整備 → 選目標與技能 → 六人逐棒接力 → 終結 → 一次爆裝 → 立即比較／裝備 → 再戰`

不以平衡為優先，只強化爽感、清晰度、操作流暢度、Build 連動與重刷動機。

## 2. 成功標準

- 375×667、390×844、430×932 與 1280×800 全程固定單畫面，無頁面捲動、裁切或 HUD 重疊。
- 「單畫面」代表一次只呈現一個主要決策，不以縮小文字或按鈕塞入所有資料。
- 一般正文至少 13px、主要資訊至少 15px；所有操作區至少 44×44px，鄰接操作保留 8px。
- 新玩家不開說明抽屜也能完成第一次任務、六棒接力、收取掉落、換裝、融合與重刷。
- 每次命中、疊層、連鎖、擊破與死亡都在對應動畫播放時才更新畫面狀態。
- 結算頁可同時呈現最多 20 件非素材掉落；素材同頁獨立顯示且不占 20 格。
- 重要效果優先以顏色、圖示、動態、音效與數字表示，詳細文字只在點擊後展開。

## 3. 已確認的根因

- 現有固定單畫面以 8–12px 文字和低於 44px 的控制項換取不捲動，造成可用但不可讀。
- 必要教學藏在預設關閉的 `?` 抽屜或螢幕閱讀器文字中，玩家只看見焦點框。
- 技能已完成最終結算後才播放事件動畫，導致 HP、狀態與死亡提前出現。
- 540 種技能形式被呈現成名稱、篩選器與大量敘述，因果關係沒有視覺化。
- 挑戰、圖鑑、昇華與敵人特性已有資料或邏輯，但沒有完整進入目前玩家流程。
- E2E 主要驗證 DOM 存在與版面容納，沒有守住閱讀性、觸控性、事件同步與視覺品質。

## 4. 產品原則

1. 每個畫面只有一個明確主要動作。
2. 玩家先看結果與可能性，再決定是否閱讀公式。
3. 角色、目標與狀態直接附著在戰場單位上，不再建立重複卡框。
4. 每次操作都提供按下、結果、下一步三層即時回饋。
5. 系統深度存在於組合與事件連動，不存在於長篇說明或乘法數值。
6. 所有非必要詳情使用單一共用底部抽屜，不同區塊不各自展開大量文字。

## 5. 第一次遊玩流程

- 任務頁只突出「開始第一場教學戰」與三個圖像步驟：選敵人、選技能、完成接力。
- 必要教學改為貼近目前操作區的可見短句，不放進說明抽屜；可略過，但不阻擋自由操作。
- 點敵人後，選取圈、血量條與命令列同步變色，立即確認目前目標。
- 點技能第一次為選取與預覽；點戰場目標或再點相同技能立即施放。
- 每位角色出招完成後，戰場光線移至下一位並顯示「布蘭完成 → 萊拉接棒」的短動態。
- 勝利後直接進入完整掉落總覽；可快速裝備、查看技能或立即重刷。

## 6. 戰鬥狀態與演出

- `simulation-core` 仍是唯一戰鬥結果來源；React、PixiJS 與播放計時不得自行決定傷害。
- 模擬結果須提供依事件排序的中立結果影格，包含受影響單位的 HP、狀態、削防與強化前後值。
- Web 播放層只控制目前顯示到第幾個影格；動畫結束後才切換到最終 BattleState。
- 重複命中採快速節奏壓縮，保留每次獨立數字與觸發，但避免數十事件造成漫長等待。
- 第 1–6 棒依序增加殘影、路徑密度、鏡頭推進、震動、音效層與終結停頓；每棒必須超越上一棒。
- 敵人只在對應擊破事件播放後才消失；Overkill、擴散與迴響必須清楚顯示來源與去向。
- 人物 HUD 僅保留名稱、精確 HP、短血條、狀態圖示；攻防與完整公式集中在命令區。
- 預覽時人物上只顯示幽靈血條與 `136→81`；不得在單位旁堆疊攻防、削弱或長句。

## 7. 技能操作與因果呈現

- 六技能格預設只顯示屬性、特化圖示、觸發狀態、預估總傷害與命中次數。
- 選中技能後展開一條視覺因果鏈，例如：`燃 4 → 消耗 → 4 爆 → 毒霧擴散`。
- 綠色代表條件現在成立；半亮代表命中後成立；暗色代表只有基礎效果，但技能仍可施放。
- 詳細抽屜才顯示攻擊＋技能＋強化－防禦、每個元件、完整目標變化與觸發說明。
- 融合技能以 2–3 個元件節點顯示實際結算順序，玩家可直接看出為何形成連技。

## 8. 20 件戰利品總覽

- 非素材掉落使用自適應密度：1–8 件大卡、9–14 件中卡、15–20 件為 4×5 網格。
- 預設全部同時可見，無隱藏卡、輪播、翻頁或捲動；素材固定為同頁緊湊數量列。
- 每格只顯示圖示、稀有度、短名稱與一個最重要的詞綴／特化；推薦物只用星號或光暈。
- 點任一格開啟唯一底部詳情抽屜；再點同一格或關閉即收起，點其他格直接替換內容。
- 詳情提供目前裝備比較、完整隨機值、核心／觸發、裝備或配置行動與搭配提示。
- 20 件在 600–900ms 內快速連續落地；高稀有度使用更強光、震動與音效，但完成後立即可操作。
- 顯示層現在就支援 20 件極限資料；實際掉落數仍由模擬決定，高階關卡日後可達 16–20 件。

## 9. 整備介面

- 隊伍頁以目前角色為主體，顯示造型、接力位置、核心數值、三件裝備與六技能摘要。
- 技能頁固定顯示目前角色與六格技能；候選區每頁只顯示六張，完整篩選收進一個抽屜。
- 裝備頁固定顯示目前角色與三個大型裝備槽；背包每頁只顯示六件候選。
- 換裝或換技能時顯示新增／失去的事件能力，例如「新增熔甲」「毒霧可追燃」，不只顯示數值差。
- 成功裝備技能後自動前往下一名角色，並以明確過場顯示完成者與目前角色。
- 結算頁的主要行動必須描述真實結果；若只導航，不得使用「已穿上」或相似誤導語意。

## 10. 任務與長期動機

- 任務卡預設只顯示敵人輪廓、主要弱點、目標掉落、最佳紀錄與挑戰進度。
- 已存在的敵人護衛與弱點特性接入目前技能結算，全部轉成可追蹤的加法增減，不使用傷害乘法。
- 挑戰整合進任務卡與結算，不增加第五個主要導航；新完成項目以獎章動畫顯示。
- 圖鑑放入次要收藏抽屜，記錄敵人、裝備核心、技能組合與區域發現。
- 現有昇華資料在乘法規則改為加法前維持隱藏；完成全區後再開放高掉落重刷模式。

## 11. 設定、失敗與降級

- 增加音量、音效、震動、動態效果與重新播放教學的設定入口。
- 音效至少區分起手、命中、疊層、觸發、彈射、擊破、稀有掉落與第六棒終結。
- 支援 `prefers-reduced-motion`；降低位移與震動，但保留數字、顏色、狀態與因果資訊。
- Pixi 載入失敗時顯示可操作的語意戰場；存檔無效時保留備份並提供清楚恢復選擇。
- 所有不可用操作須顯示原因；不使用無反應按鈕或只在隱藏狀態列回報錯誤。

## 12. 驗證與交付

- 純函式測試：事件影格逐步更新、加法敵人特性、技能因果摘要、20 件密度模型。
- 元件測試：20 件全部可見、素材同頁、唯一詳情抽屜、技能／裝備真實行動、可見教學。
- 幾何測試：人物 HUD 不碰撞、字級與觸控區達標、戰場與命令區不重疊。
- E2E：第一次完整閉環、20 件極限結算、裝備／技能後重刷、存檔遷移、Pixi 降級。
- 視覺快照：任務、戰鬥待命、技能預覽、逐事件播放、終結、20 件結算、技能與裝備頁。
- 尺寸固定驗證 375×667、390×844、430×932、1280×800；無水平或垂直頁面捲動。
- 每個實作批次必須是一個可由玩家直接感知的完整成果，使用直接 TDD、一次整合審查、一次聚焦修正，再執行完整 gate 與 Cloudflare 線上驗證。

## 13. 非目標

- 不新增 PVP、公會社交、角色等級線性成長、抽卡戰術或死亡傳遞。
- 不以數值平衡、經濟平衡或乘法膨脹為優先。
- 不重寫 simulation-core 的既有責任邊界，也不以 UI 層決定任何戰鬥結果。
- 不在第一批擴充新關卡；先讓現有 12 場狩獵、Build 與掉落完整可見且值得重刷。
